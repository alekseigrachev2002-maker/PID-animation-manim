## Итоги (ноябрь 2026)

- **Подключение моторов (после апробации):** `motors(левый, правый)`. Левый мотор — канал M2 Motor Shield
  (D7 — направление, D6 — ШИМ), правый — M1 (D4, D5). Моторы стоят зеркально, инвертирован левый:
  `motors(int16_t left, int16_t right, bool invLDir = true, bool invRDir = false)`. В модели `Motor.swapped = False`
  (на модель инверсия не влияет: она про пины направления, а не про то, какое колесо первое).
- **Регулятор (урок 2):** `err = L − R`, `control = kp·err + kd·(err − errOld)`,
  `motors(speed + control, speed − control)`, шаг — `delay(10)` в `loop()`. Белое выше черного: линия слева →
  L меньше → err < 0 → левое колесо медленнее.
- **Датчики линии (два случайных из 100):** белое 920 и 958, черное 191 и 216. Разница датчиков ≈ 4 %:
  на прямой err ≈ −38 вместо 0 — регулятор это «проглатывает», `sensorBalance` не нужен.
  В модели (`params.Sensor`) датчики одинаковые — среднее замера: белое 939, черное 204.
- **Порог перекрестка:** 300 — найден на машинке; датчики замечают линию раньше, чем робот на нее
  наезжает, поэтому он останавливается на ней.
- **Энкодеры (после апробации):** 350 тиков на оборот колеса (7 на оборот вала × редуктор 1:50; прежний замер
  431 — устарел); левый — D2 (C1, прерывание) / D8 (C2), правый — D3 / D9, знак правого инвертирован.
  Шлейф: зеленый и черный — мотор (M2, M1), оранжевый — VCC, красный — GND, белый — C1, желтый — C2.
- **Езда по полу (`driveTest` тестового скетча, апробация)** — в модели `Motor.curve` и `Motor.tau`:

  | ШИМ | Скорость | Выбег после `motors(0, 0)` | Поправка, чтобы ехать прямо |
  |---|---|---|---|
  | 150 | ~280 мм/с | ~30 мм | `motors(138, 150)` |
  | 255 | ~435 мм/с | ~60 мм | `motors(244, 255)` |

  Правый мотор отстает тем сильнее, чем больше нагрузка: в воздухе 1 %, на полу 4–8 %, при сильном трении 19 %.
  В модели моторы одинаковые. Инерция колеса `tau` = 0,11 с — по выбегу: путь ≈ v·tau (30 мм с 280 мм/с).
- **Датчики над полом — 10 мм.** По datasheet TCRT5000 (рис. 9) на 10 мм сигнал ≈ 30 % от пика (пик на 2,5 мм);
  ширины пятна в datasheet нет. Оценка по геометрии — пятно 5–8 мм, σ ≈ 2,5–3,5 мм; в модели `Sensor.sigma` = 2,5.
- **kp и kd у участников:** kp = 0,15–0,2, kd = 1 (`delay(10)`). Без поправки модель по алгоритму урока давала
  kp ≈ 0,05 — в 3 раза меньше: в модели не было трения шариковой опоры и колес о пол в повороте. Добавлен
  `Motor.turn_share` = 0,4 — доля разницы скоростей колес, которая доходит до поворота. **Не замер, подобран:**
  с ним `tune.py` (алгоритм урока на повороте R = 150 мм) дает: вписывается с kp = 0,13, «почти» — 0,12,
  с ним kd от 0,9; в сценах kp = 0,12, kd = 1.

## Скетч: лог err по таймеру

Регулятор раз в 5 мс (как в модели), err пишется в память, а не в Serial: печать во время езды сама дает задержку. Хватает на 2 с езды (Uno: 400 × 2 байта). После прогона моторы стоп, лог печатается в Монитор порта.

```cpp
// вставить вместо followLine() и loop() скетча урока 2

const float speed = 150;
const float sensorBalance = 1.0;
const float kp = 0.3;
const float kd = 0.0;
const uint16_t PERIOD_MS = 5;
const uint16_t N = 400;           // 400 × 5 мс = 2 с

int16_t logErr[N];
uint16_t n = 0;
uint32_t tNext = 0;
float errOld = 0;

void followLineTimed() {
  float err = analogRead(LEFT_SENS) * sensorBalance - analogRead(RIGHT_SENS);
  if (n == 0) errOld = err;       // без рывка D на старте
  float control = err * kp + (err - errOld) * kd;
  motors(speed - control, speed + control);
  errOld = err;
  logErr[n++] = (int16_t)err;
}

void loop() {
  if (tNext == 0) { delay(2000); tNext = millis(); }   // 2 с, чтобы поставить робота
  if (n < N) {
    if (millis() >= tNext) { tNext += PERIOD_MS; followLineTimed(); }
    return;
  }
  motors(0, 0);
  Serial.println("t_ms err");
  for (uint16_t i = 0; i < N; i++) {
    Serial.print(i * PERIOD_MS); Serial.print(' '); Serial.println(logErr[i]);
  }
  while (true) {}
}
```
