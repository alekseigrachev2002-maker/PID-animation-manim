# Замеры для модели

Что измерено на машинке и как это вошло в модель (`params.py`). Сверху — действующие значения: замеры
апробации (ноябрь 2026) верны. Отдельно помечено то, что оценено или подобрано, и то, что еще стоит измерить.

Общее для новых замеров: робот на полу с тем же покрытием, что на уроке, без USB-кабеля (кабель тянет
робота — см. «Трение в повороте»), аккумулятор заряжен. Результат без кабеля — через EEPROM, как в `driveTest`.

## Подключение (тестовый скетч RobotTest)

| Что | Как подключено |
|---|---|
| Левый мотор | канал M2 Motor Shield: D7 — направление, D6 — ШИМ |
| Правый мотор | канал M1: D4 — направление, D5 — ШИМ |
| Инверсия направления | моторы стоят зеркально, инвертирован левый: `motors(left, right, invLDir = true, invRDir = false)` |
| Левый энкодер | D2 — C1 (прерывание), D8 — C2 (направление) |
| Правый энкодер | D3 — C1, D9 — C2; знак правого инвертирован |
| Датчики линии | A0 — левый, A1 — правый (Troyka, S-V-G) |
| Шлейф мотора | зеленый и черный — мотор (M2, M1), оранжевый — VCC, красный — GND, белый — C1, желтый — C2 |

- Энкодер: **350 тиков на оборот колеса** (7 на оборот вала × редуктор 1:50). Колесо ⌀ **43 мм** (`WHEEL_D`).
- В модели `motors(левый, правый)`: первый аргумент — левое колесо (`Motor.swapped = False`); инверсия направления
  — про пины, на модель не влияет.

## Датчики линии

| | Левый | Правый | В модели (`Sensor`) |
|---|---|---|---|
| Белое | 920 | 958 | 939 (среднее) |
| Черное | 191 | 216 | 204 (среднее) |

- Два случайных датчика из 100. Разница ≈ 4 %: на прямой err ≈ −38 вместо 0 — регулятор это «проглатывает»,
  `sensorBalance` не нужен. В модели датчики одинаковые.
- Белое выше черного: линия слева → L меньше → err < 0 → левое колесо медленнее.
- Высота над полом — **10 мм**. По datasheet TCRT5000 (рис. 9) на 10 мм сигнал ≈ 30 % от пика (пик — 2,5 мм).
  Ширины пятна в datasheet нет; оценка по геометрии — пятно 5–8 мм, σ ≈ 2,5–3,5 мм; в модели `Sensor.sigma` = 2,5.
- Порог перекрестка — **300** (`#define THRESHOLD 300`), найден на машинке: датчики замечают линию раньше, чем
  робот на нее наезжает, и он останавливается на ней.
- Линия — 30 мм (PDF полей 2400×1500). Поле 2: углы R = 150 мм, S-кривая R ≈ 180–750 мм.

## Езда по полу (`driveTest`, без кабеля, результат в EEPROM)

| ШИМ | Скорость | Выбег после `motors(0, 0)` | Поправка, чтобы ехать прямо |
|---|---|---|---|
| 150 | ~280 мм/с | ~30 мм | `motors(138, 150)` |
| 255 | ~435 мм/с | ~60 мм | `motors(244, 255)` |

- Правый мотор отстает тем сильнее, чем больше нагрузка: в воздухе 1 %, на полу 4–8 %, при сильном трении 19 %.
  С проводами и энкодером это не связано (разница растет плавно с нагрузкой) — у правого мотора меньше момент
  или туже редуктор. Для езды по линии не страшно: ПД-регулятор компенсирует; для езды прямо без линии нужна
  поправка, и она зависит от скорости (таблица). **В модели моторы одинаковые.**
- В модели: `Motor.curve` — скорость от ШИМ по точкам (50 → 0, 150 → 280, 255 → 435), между ними прямая;
  `Motor.tau` = 0,085 с — подобрана вместе с задержкой `Motor.delay` = 20 мс под выбег 30 мм с ШИМ 150
  (с ШИМ 255 модель дает ~47 мм против ~60 — выбег на большой скорости модель занижает).
- Трогание стоящего колеса — ШИМ 67, остановка крутящегося — ниже 50 (`pwm_start`, `pwm_stop`; ранний замер).

## Регулятор

- Урок 2: `err = L − R`, `control = kp * err + (err − errOld) * kd`, `motors(speed + control, speed − control)`,
  `speed = 150`, `delay(10)` в `loop()`.
- **Период цикла — 10,3 мс** (оценка по коду урока 2, без Serial): `delay(10)` + два `analogRead` (~0,11 мс каждый)
  + расчет на float и `motors()` (~0,05 мс). В модели `Controller.period` = 0,0103 с. С `Serial.print` в цикле период
  больше — перед ездой вывод в порт закомментировать.
- **У участников:** kp = 0,15–0,2, kd = 1. Модель по алгоритму урока (`tune.py`, поворот R = 150 мм) дает «почти»
  kp = 0,09, проходит с kd от 0,5; в сценах kp = 0,09, kd = 1 — тот же порядок.

## Трение в повороте — оценка, не точный замер

`Motor.turn_share` = 0,55 — доля разницы скоростей колес, которая доходит до поворота (остальное съедают шарик
и колеса, скребущие пол). Одно значение для всех сцен.

| Замер | Энкодеры | Вывод |
|---|---|---|
| Разворот `motors(150, -150)` 3 с | L 1219 тиков, 470 мм; R −1190, −459 мм | колеса ~155 мм/с вместо 280 → доля ≈ 0,55; угол по энкодерам ≈ 430° (если колеса не проскальзывали) — **взят в модель** |
| Дуга `motors(180, 150)` 2 с | L 1705 тиков, 658 мм; R 931, 359 мм | поворот ≈ 138° — в 3 раза больше, чем без трения; **не взят**: робота тянул провод, возможна пробуксовка |

Оба замера — с подключенным кабелем. Переснять без кабеля (запись в EEPROM, как `driveTest`) и с отметкой угла
на полу — тогда трение станет замером.

## Скетч: лог err без кабеля

Вместо `followLine()` и `loop()` скетча урока 2 (`motors()`, `LINE_L`, `LINE_R` — оттуда). Регулятор раз в 10 мс,
err пишется в EEPROM (200 × 2 байта = 2 с езды; у Uno 1 КБ). Подключили USB — плата перезагрузилась —
в порт печатается прошлый заезд, через 3 с новый заезд.

```cpp
#include <EEPROM.h>

const float speed = 150;
const float kp = 0.09;            // свои значения
const float kd = 1.0;
const uint16_t N = 200;           // 200 × 10 мс = 2 с
const uint16_t KEY = 0x4552;      // признак, что в EEPROM лежит лог

void printLog() {
  uint16_t key;
  EEPROM.get(0, key);
  if (key != KEY) { Serial.println(F("EEPROM empty")); return; }
  Serial.println(F("t_ms err"));
  for (uint16_t i = 0; i < N; i++) {
    int16_t e;
    EEPROM.get(2 + 2 * i, e);
    Serial.print(i * 10); Serial.print(' '); Serial.println(e);
  }
}

void setup() {
  // pinMode моторов — как в уроке 2
  Serial.begin(115200);
  printLog();
  delay(3000);                    // поставить робота, отключить кабель
  float errOld = analogRead(LINE_L) - analogRead(LINE_R);
  for (uint16_t i = 0; i < N; i++) {
    float err = analogRead(LINE_L) - analogRead(LINE_R);
    float control = kp * err + kd * (err - errOld);
    motors(speed + control, speed - control);
    errOld = err;
    EEPROM.put(2 + 2 * i, (int16_t)err);   // запись ~3,3 мс — цикл длиннее, чем в уроке; учесть при сравнении
    delay(10);
  }
  motors(0, 0);
  EEPROM.put(0, KEY);
}

void loop() {}
```

## Архив: первые замеры (устарели)

Энкодеры до апробации, `encSpeed_test` (робот крутится на месте), считали 431 импульс на оборот (5 оборотов рукой
= 2156) — сейчас 350. Таблица — для истории: скорости в ней посчитаны с неверным числом импульсов и частично
от USB.

| ШИМ | от USB, M1 / M2, Гц | аккумулятор, M1 / M2, Гц | аккумулятор, на полу |
|---|---|---|---|
| 80 | −521 / 488 | −653 / 620 | — |
| 150 | −759 / 737 | −920 / 902 | — |
| 255 | −881 / 870 | −1068 / 1064 | −1333 / 1346 |

Что из этого остается верным:
- скорость растет с ШИМ все медленнее (от 150 до 255 заметно меньше, чем от 50 до 150) — так и в `Motor.curve`;
- скорость зависит от напряжения: мост L298P теряет ≈ 1,5–2,5 В; при VCC ниже ~6,5 В (разряд аккумулятора, минус
  ~0,4 В на диоде) DC-DC выходит из стабилизации, и скорость начинает зависеть от заряда.
