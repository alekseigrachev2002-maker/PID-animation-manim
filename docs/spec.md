# ПИД на роботе по линии — спецификация анимаций Manim (7 ноября 2026)

Анимации идут между слайдами презентации. Полная блок-схема и словесные пояснения — на слайдах, в анимации только короткая фраза этапа и одна формула.
Раскадровка (канвас): https://claude.ai/artifact/WkiVoK2BRxNNAPk8PSMQ7i — утверждён только макет сцены 1 (кадры «Сцена 1»), остальные кадры в старой компоновке.

## Макет (общий для всех сцен, масштаб не меняется)
- Кадр 16:9 (эталон 1280×720 px). Слева графики — 2/3 ширины, справа сцена движения — 1/3.
- Масштаб робота фиксирован: 1.6 px/мм, середина оси колёс ниже центра панели (больше видно впереди). Шасси непрозрачное, матовое тёмно-серое (варианты в Style: глянец, пунктир линии под шасси), линия — матовый чёрный. На платах в оптическом центре — светящаяся метка, яркость = нормированный сигнал АЦП (белое → чёрное). Робот стоит в одной точке (центр правой панели), под ним едет «мир» (трасса и следы), ориентация «север вверх». Панель графиков — непрозрачный прямоугольник с высоким z_index поверх трассы.
- Сверху: фраза этапа (глагол + объект, 2–4 слова, меняется только на смене этапа: «Считаем ошибку», «Подбираем P», «Вводим D») + один блок с текущей формулой (`e = L − R`, `u = kp·e`, `u = kp·e + kd·Δe`), прямым шрифтом без курсива. Обозначения как в коде: `u`/`control`, `kp`, `kd`.
- Снизу легенда в одну строку.
- Цвета: L — синий #4C8DF6, R — оранжевый #F59E0B, e — зелёный #34D399, D-часть — розовый #E879F9. Цвет платы датчика = цвет его сигнала. Фон графиков #0E1117, поле #EEECE5, линия #151515.
- Стрелку «вперёд» не рисуем: направление задаёт ёлочка протектора.
- Шапка: «**Фраза этапа:** пояснение шага» (пояснение 4–6 слов, приглушённым цветом, меняется на каждом шаге; фраза — только на смене этапа), блок формулы у правого края панели. Подписи на графике не нужны — пояснения живут в шапке.

## Геометрия (мм; начало — середина оси колёс, +y вперёд)
- Шасси: круг Ø160, вырезы под колёса 24×48 R4, x от ±50 до ±74. Без крепёжных отверстий.
- Колёса: Ø44 (43–45), ширина ≈ 20, центры x = ±62, колея 124. Сверху — прямоугольник с ёлочкой; фаза протектора = пройденный путь / R, видимая половина проецируется через sin φ.
- Датчики: плата 40×10 (EasyEDA PCB_PullDown). Крепёжное отверстие Ø3 в (±23.789, 73.214), от него до переднего края платы 31.5; переднее отверстие в 2.5 от края; центр TCRT в 10 от края → оптический центр (±23.789, 94.714). Плата торчит из-под шасси.
- TCRT5000 на нижней стороне платы, сверху не виден — не рисуем.
- Линия: ширина 10.
- Следствие: датчики в 47.6 друг от друга при линии 10 → мёртвая зона ≈ ±15 мм / ±10° (e = 0, оба на белом). Модель при σ = 2.5: |e| < 1 до ±11 мм / ±6.5°; e > 100 с ±18 мм / ±10°.

## Регулятор (порт followLine из lesson-02)
- `e = L·sensorBalance − R`; `u = kp·e + kd·(e − e_old)`; `motors(speed − u, speed + u)`, constrain ±255; speed = 150.
- Знак (в модели сейчас: белое выше, `Motor.swapped = True` — правый мотор на IN1/IN2, заглушка до теста 0): при левом моторе на IN1/IN2 код рулит верно, только если на чёрном АЦП выше. Схема платы (EasyEDA, «Analog line sensor» → PullDown_sheet): фототранзистор в верхнем плече, R2 10k на землю, C2 0.1 мкФ (τ ≈ 1 мс) → **на белом выше**. Раз робот ездит, в подключении есть перестановка (датчики A0/A1, моторы IN1/IN2–IN3/IN4 или полярность мотора) — выяснить тестом 0 из `docs/measurements.md`, модель поправить под реального робота.
- Рекомендация: считать регулятор по таймеру millis() с фиксированным периодом, иначе kd зависит от частоты loop() (при кГц-цикле D почти нулевая).

## Физическая модель (model.py + track.py, без Manim)
- Датчик: гауссово пятно σ на полосе, покрытие через scipy.special.erf; расстояние до линии — cKDTree по точкам осевой; перекрёсток: 1 − (1 − c1)(1 − c2). ADC = W + (B − W)·cov + шум (шум — параметр, по умолчанию 0). Значения W и B отдельно для L и R.
- Моторы: v_target = sign(PWM)·k·max(0, |PWM| − PWM₀), инерция v̇ = (v_target − v)/τ. Гистерезис трения: стоящее колесо трогается при |ШИМ| > 67, крутящееся едет до |ШИМ| ≈ 50 (замер; 67 — при обоих стоящих колёсах), k = v(150)/(150 − 50). Трассу подбираем так, чтобы колёса не вставали: тогда сдвиг 50 одинаков для обоих колёс и в руление не входит; пороги остаются в модели как проверка.
- Кинематика: v = (vL + vR)/2, ψ̇ = (vR − vL)/b, ẋ = −v·sin ψ, ẏ = v·cos ψ.
- Регулятор дискретный (ZOH между тиками), робот непрерывный: solve_ivp от тика до тика с dense_output → непрерывная траектория, traj.at(t).
- Без τ при большом P перерегулирования нет (датчики впереди демпфируют) — τ обязательна. Устойчивость линейной модели с одной инерцией: L > v·τ, не зависит от kp: большой P раскачку не даёт, проверено в quicklook.
- Чистая задержка команда → колесо (`Motor.delay`) даёт классическую картину «P растёт → раскачка». Заглушка 20 мс: kp 0.1–0.3 спокойно, 0.5 — затухающие перехлёсты, ≥ 0.8 — незатухающая раскачка с периодом ≈ 0.33 с; kd ≈ 1–2 её гасит, с D можно kp 0.8–1.2. Реальную задержку подогнать по периоду раскачки робота на прямой при большом kp.
- Сцена 1 (поворот руками): ψ(t) задаётся, датчики через ту же функцию.
- Заглушки до замеров: τ = 80 мс, v(150) ≈ 300 мм/с, σ = 2.5, W/B ≈ 120/860, период регулятора 5 мс. Скорость измерить, τ подогнать по реальному логу err(t).

## Архитектура
Сначала расчёт, потом проигрывание: физика считает Trajectory (t, x, y, ψ, L, R, e, uP, uD, ШИМ, фазы колёс), сцена проигрывает её одним ValueTracker t. Кэш в .npz по хэшу параметров.
```
params.py        # frozen dataclass'ы: геометрия, модель, регулятор, макет/стиль
track.py         # формы линий + distance(); осевые линии нужны и визуалу
model.py         # датчик, моторы, кинематика, регулятор, simulate(), prescribed()
visuals/robot.py # Robot(VGroup): set_pose(), set_wheel_phase()
visuals/panels.py# макет, графики, шапка, легенда; мм → единицы Manim только здесь
scenes/base.py   # PIDScene: макет, трекер t, bind(traj)
scenes/sN_*.py   # одна сцена = один файл, сценарий внутри
quicklook.py     # matplotlib для подбора параметров
```
- Растущие кривые: set_points_as_corners(pts[:i]) каждый кадр, либо pointwise_become_partial(full, 0, i/N) — проверить, что доля по сегментам, а не по длине.

## Сцены
1. Поворот на месте ±18° над прямой: L, R на графике → L, R полупрозрачные, появляется e = L − R, ещё одно качание. Видно плато e = 0 (мёртвая зона).
Сцены 2a–2c проходят стандартную ручную настройку: P до раскачки и чуть назад → D гасит → с D поднимаем P или скорость.
2a. Подбор P (`scenes/s2a_p.py`): прогоны из одной позы (поворот 15°, задержка 20 мс — заглушка): kp = 0 (уходит с линии) → 0.1 (медленно) → 0.5 (перехлёсты) → 0.8 (раскачка) → 0.3 (быстро и без раскачки). После прогона кривая e становится призраком, робот отматывается к старту. У колёс числа ШИМ.
2b. Ввод D: тот же старт, kp из 2a; kd = 0 → перехлёсты (призрак), kd > 0 → без перехлёста; на графике uP и uD отдельно, uD срабатывает первым.
2c. С D поднимаем P (или скорость): kp, раскачивавший робота в 2a, с D едет спокойно. Где показывать (та же прямая или трасса с поворотами) — решить.
3. Перекрёсток: L и R одновременно в чёрное → e ≈ 0 (синфазное подавление); роль sensorBalance; при курсе ψ датчики заходят с разницей ≈ 47.6·tg ψ / v → короткий выброс e, D его усиливает.
